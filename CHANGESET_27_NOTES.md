# Set 27 — fixture account enrollment signer

This adds `Wallet.SignAccountChallenge` for the paired account authority's
versioned enroll/recover contract. The caller pins the authority independently
of the challenge. Validation binds chain, fixture profile, retained public root,
gym public key and gym ID before and inside the existing private-operation
lease. Only the two independently published zero256/incrementing256 identity
pairs are supported. Derivation/signing uses bounded local work and clears owned
private buffers. The lease covers bounded wallet DB reads and signing, with no
network, provider interaction or recovery-file export.

The signer does not authenticate a login, check service time, consume a
challenge, authorize a current session or bypass the post-reset hold. Those
checks belong to the durable paired account authority. User-approved D72 is a
24-hour hold after verified reset, allowing view and existing-wallet mining but
blocking recovery export, withdrawals, fighter transfer, authority changes and
marketplace purchases/listings. Distinct resets restart the hold; replay of the
same event does not. Old sessions are revoked immediately.

Existing wallet private-password rotation is unchanged. Tests rotate the
password, close and reopen each fixture wallet, then prove identical retained
recovery and independent enrollment/recovery signatures. Fresh restore using
the exported bundle and a different wallet password reproduces those signatures.
Login passwords and wallet encryption are separate. A backup remains a copy of
recovery authority; exclusive migration and production signup/custody/profile
allocation are not implemented.

The shared binary challenge/signature contract and independent Python oracle
live in paired `gymaccount`; no opaque generated bytes or implementation-derived
expected signatures are used. The desktop adapter's separate account constructor
chooses these two fixtures explicitly while preserving the old zero256-only mode.
It performs enrollment signing through this narrow in-process API, never RPC or
webview secret plumbing.

  cross-account and unsupported fixture refusal.

  (1.447 s). The independently authored reference race suite passes (1.579 s).
- Desktop adapter compile-only check passes (0.357 s).
- The same wallet signer lifecycle tests pass under the race detector

- Desktop two-fixture constructor/signing/reopen/restore/isolation behavior
  passes (15.431 s), preserving the old zero256-only mode and refusing unknown

- All six wallet modules build; wallet, shared account package and desktop
